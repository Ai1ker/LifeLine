# P2P 预留接口与后续接入

当前交付是本地双人游戏。`Runtime/Networking` 已有身份、命令、快照和主机验证的代码边界，但没有 `IGameTransport` 的具体网络实现，没有真正 Host/Join、Steam 初始化、房间发现或远端快照应用。主菜单没有在线按钮。切换 `onlineView` 只会改变相机与名字显示，不会建立连接。

## 当前已经存在的接口

| 类型 | 当前职责 | 实际限制 |
| --- | --- | --- |
| `IGameTransport` | 定义 Host/Join/Leave、发命令/广播快照、连接状态及加入/离开/收包事件 | 只有接口，无 Mirror/Steam 适配器或自动消息循环 |
| `ILocalPeerIdentity` | 提供 SteamId、DisplayName 的读取边界 | 没有调用平台SDK；字符串本身不是已验证身份 |
| `NetworkPeerIdentity` | peerId、steamId、displayName、角色的 DTO | 当前本地名字是占位配置 |
| `NetworkCrewCommand` | 版本、sequence、tick、senderPeerId 与 `CrewCommand` | 版本1；尚未实现线上序列化、确认与重传 |
| `SessionNetworkSnapshot` | 种子、时间、日数、船体、电量、船位置、双角色状态、仓库、升级、电台阶段 | 不包含所有作业/修理/敌人/掉落/货箱等状态；没有生成/消费/应用循环 |
| `RemoteCrewInputSource` | 接收命令后保留移动/按住动作，消费按钮边沿，输入超过.3秒无更新时返回中性命令 | 是输入适配器，不能自行收网络包或认证对端 |
| `SessionAuthority` | 对调用方已认证的 peer 检查协议、身份与角色匹配、递增 sequence，并限制 move 向量长度 | 只有验证入口；没有 transport 订阅或完整主机生命周期 |

`SessionAuthority.snapshotRate=20` 与 `simulationTick` 是公开预留字段，目前没有按20Hz发送快照的实现。不能据此声称已提供状态同步、延迟补偿、断线恢复或反作弊。

`RemoteCrewInputSource.ReadCommand()` 只清 jump/interact/melee/fire/signal/bait/hide/pause 边沿，不清 `interactHeld`，这是持续扶起所需的正确行为。新的 Push 包应持续携带按住状态，松开必须发送 false；禁用或超时后返回中性命令。按住状态不能被一次按键边沿的消费顺带清掉，也不能靠重发旧 press 包延长交互。

`ApplyAuthenticatedRemoteCommand(authenticatedPeerId, packet)` 要求认证 peerId 与配置远端、包内发送者和角色一致，拒绝重复/倒退 sequence，再把命令交给对应 `RemoteCrewInputSource`，通过 `CrewActor.SetExternalInput(...)` 接管主机上的远端角色。本地键盘 map 会被禁用；镜头仍跟随同一个稳定角色根。

这里的 `authenticatedPeerId` 必须由后续连接适配器从真实连接认证结果提供，不能直接相信客户端自报的 SteamID。当前校验还不是完整网络安全层：有限数值、tick窗口、速率、sequence回绕、角色分配/重新连接和协议迁移都需要在实际联网版本补齐。

## 目标架构：主机权威

未来建议让 Mirror 承载网络对象/消息生命周期，并选择与其版本兼容的 Steam 传输；平台身份由独立适配器实现 `ILocalPeerIdentity`。本轮没有安装或假装接通这些适配器，也没有锁定未经验证的传输包版本。

主机运行 `GameSession`、世界生成和所有经济/战斗判定。客户端发送自己的意图，不直接写共享仓库、制作进度、维修、掉落、伤害、电量、绞盘登船或结局。主机验证后消费输入，在固定模拟时序中结算，再向客户端发送状态与可靠事件。

建议的数据路径：

1. 本机 Input System 生成带角色的命令；连接适配器补 peerId、递增 sequence 与 tick。
2. Steam/Mirror 连接认证与角色分配完成后，将已认证的远端命令送入主机的 `SessionAuthority`。
3. 主机角色读取命令，`GameSession` 处理交互、收集、战斗与共享状态。持续动作必须定期发状态，按钮边沿必须有可靠的一次性语义。
4. 主机广播增量/全量状态和可靠事件；客户端对展示位置插值，需要时做本机预测与权威纠正。客户端不能同时再运行一套独立权威经济或敌人模拟。
5. 客户端 `SetNetworkView(true, localRole)` 使用自己的完整视口；Host/Client 按本地身份显示名字，不使用本地双人分屏假装两台机器联机。

## Steam App ID 480 的位置

480 是后续开发测试所用的 App ID 配置，不等于已经提供游戏的 P2P 实现。要真正联机，还需初始化合适的平台SDK、获得身份/好友信息、使用匹配 Mirror 的 Steam 传输、完成会话发现/邀请和连接生命周期，并在两台设备上验证。当前源码没有完成这些工作，也没有因为填写480就获得 Host/Join 能力。

开发版本可以由平台适配器返回 SteamID 和显示名，再映射至 `NetworkPeerIdentity`。显示名仅用于展示，权限以连接认证后分配的 peer/role 为准；显示富文本前还需要处理不可信文本。后续正式发布应使用项目自己的平台配置与审核流程。

## 下一阶段必须补齐的状态与规则

- 实体稳定 ID、可靠 spawn/despawn，种子与生成参数一致性；真实货箱 contents、attached/consumed 和掉落物同步，不能客户端随机补资源。
- 制作队列的 jobId、owner、配方、基准起始tick、进度、独立QTE尝试；服务器校验QTE时间，避免远端直接提交“成功”。
- 站点占用、修理授权与四故障清洁/匹配状态、引擎损坏版本、发电节奏、电鳗/炮塔/鱼buff及过期时间。
- 船与两角色的位置、速度、甲板/水下、氧气、命中容量、倒地/昏厥、5秒扶起、绳限制和船长授权登船；新增 `interactHeld` 必须跟随持续输入状态发送。
- 敌人、鱼枪投射物与召回、炮塔射击和命中、防重放/限速、客户端预测与纠正；保持一个权威伤害源。
- 断线时冻结/撤销该连接控制并显示明确状态。.3秒中性输入是当前的止动保护，不是断线重连或主机迁移。不要在在线会话中不加判断地将离线远端角色切回本机键盘代打。
- 完整协议版本协商、快照应用与晚加入、暂停策略、结局/退出清理、Steam认证与角色解绑。当前本地 `Pause` 会设置 `Time.timeScale=0`，不能原样当作多人网络暂停协议。

## 后续联机验收

先验证真实两设备的连接、身份与角色归属，再覆盖高延迟、丢包、重复/过期命令、重复制作/拾取、货箱交接、持续扶起中断、输入超时、断线与重连。两端共享资源、配方结果、敌人生命和结局应由同一主机状态决定；单独切换 onlineView 或本机调用接口不构成联机验收。
