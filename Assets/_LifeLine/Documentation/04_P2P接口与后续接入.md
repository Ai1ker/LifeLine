# Steam 双人联机

联机试玩使用 Mirror v96.11.6、FizzySteamworks 6.0.1、Steamworks.NET 2025.164.0 和测试 App ID 480。打开 Steam 并登录。两台 Windows 设备使用同一游戏测试包和不同的 Steam 账号。

1. 房主点主菜单的「联机模式」，再点「创建房间」。已有联机存档时可以选择继续那次航程或创建新航程。
2. 把界面上的六位房间码发给队友。队友在「加入房间」输入房间码。房间最多两人，显示双方 Steam 昵称。
3. 两人各选一个职责。只有选好一位船长和一位潜水员后，房主才能点「开始游戏」。加载条显示准备传输、等待队友、加载场景和接收房主初始状态的进度。双方完成身份和职责验证后才加载航程。
4. ESC 菜单只暂停打开菜单的玩家输入，队友和航程继续运行。来宾退出或连接中断时，房主的航程暂停并显示房间码。来宾用原 Steam 账号和房间码回来，接回原职责及当前游戏状态。房主退出后房间解散，房主可以通过新房间读取原有联机存档。
5. 两边默认 WASD 移动，W 跳跃，E 互动和采集，Space 近战与校准，Q 鱼枪。潜水员按 B 显示或收起带有逐格物品名称的背包。ESC 的设置可以改绑，联机键位独立保存。本机全屏跟随本机控制的角色，显示可见角色头顶的 Steam 昵称。交互提示显示在当前玩家可操作物件的上方。本地双人保留下方背包栏，重叠时船长画在前面。联机重叠时本机角色画在前面。

房主拥有一个独立的联机存档槽，路径为 `Application.persistentDataPath/LifeLine/Online/<SteamID>/voyage-v1.json`。白天自动保存，暂停可手动保存，正常退出航程时保存当前可继续的进度。房间码和 Steam 连接凭据不写进存档。来宾重新进入活动房间时，读取的是房主当时的状态。

## 开发入口

| 内容 | 入口 |
| --- | --- |
| 安装固定版本依赖 | 工作目录 `tools/Install-UnityOnlineDependencies.ps1 -UnityProject <工程目录>` |
| 导入代码 | `tools/Import-UnitySource.ps1 -UnityProject <工程目录>` |
| 在原主菜单增加入口及预制体 | Unity 菜单 `LifeLine/Online/Apply Steam Co-op Menu` |
| 房间菜单 | `OnlineRoomPanel`，UGUI 预制体与可编辑中英本地化表 |
| Steam 初始化、找房、成员与职责 | `Runtime/Networking/OnlineRoomService.cs` 及 `Steam/SteamRoomService.cs` |
| P2P 消息与 Steam 身份验证 | `Steam/MirrorGameplayTransport.cs` |
| 场景、重进与保存 | `OnlineVoyage.cs`、`OnlineSaveSlot.cs` |
| 状态与设备面板 | `OnlineWorldFrame.cs`、`GameSessionOnlineReplica.cs`、`CrewStationPanelOnline.cs` |
| 联机键位 | `CrewInputReader` 使用 Captain action map，覆盖值存在 `Lifeline.Bindings.v1.Online` |

固定依赖安装在 `Assets/ThirdParty/Mirror` 和 `Packages`。Windows 构建会在 EXE 同目录写入 `steam_appid.txt`。测试版应连同该文件、`LifeLine_Data`、`MonoBleedingEdge` 和同目录库一起分发。

房主运行模拟和 QTE 判定。来宾约每 20ms 上报输入，短按音符也会缓存至发送。位置、绳长和正在操作的设备动态参数使用约 30 Hz 二进制消息，过期消息丢弃，来宾逐帧插值或外推。设备外推最多 0.16 秒。房主对当前面板的来宾节奏输入最多补偿 0.18 秒。设备按钮、材料费用、命中和捕获仍由房主控制。作业和设备结构状态约每 80ms 更新，地图物资和门约每 650ms 检查一次并按需发送。

Steam 的 App ID 480 供这次原型联调使用。当前使用 FizzySteamworks 的 SteamNetworking 直连路径，直连不可用时允许 Steam 中继。房间有游戏和协议标识，当前联机握手版本为 5。房主身份固定，退出后需要另建房间。`Player.log` 中的 `LifeLine Steam` 和 `LifeLine online` 日志可区分传输启动、来宾接入、身份验证和初始状态超时。

2026-11-19 联机故障复测中，旧版 SteamSockets 能创建监听，但本机 Steam 中继报告失败。修复版的 App ID 480 直连监听已用真实 Steam 账号启动。PlayMode 使用模拟传输和 Input System 键盘事件验证先握手再进场、房主移动、来宾移动指令、改绑、断线暂停和重进恢复。跨机器联机需两台设备都使用修复版进行验证。

协议 3 的回归额外覆盖阶段加载条、按 B 显示背包、丢弃过期位置、来宾帧间移动和近战表现。Unity EditMode 155 项和 PlayMode 48 项通过，Windows 严格构建 0 错误。

参考 [Steam 房间文档](https://partner.steamgames.com/doc/features/multiplayer/matchmaking)、[Mirror 的 Steam 传输说明](https://mirror-networking.gitbook.io/docs/manual/transports/fizzysteamworks-transport)及 [FizzySteamworks](https://github.com/Chykary/FizzySteamworks)。
