## 整数承伤、攻击与实体接触

| 对象或升级 | 承伤 / 伤害单位 |
| --- | --- |
| 船长 | 2单位，始终不受潜水服升级影响 |
| 潜水员基础 | 2单位 |
| 潜水服T1 / T2 | 3 / 4单位 |
| 潜水服新增T3 | 仍4单位；每次25%免疫；每级费用仍1铁板+2纤维束 |
| 食人鱼 / 普通鲨 / 白化鲨 | 对玩家分别1 / 2 / 2单位 |
| 深影撕咬、冲刺 / 水弹 | 2 / 1单位；对船仍近战随机5–10，水弹每发5 |
| 雷击 | 直接耗尽当前容量使其倒地或昏厥；舱内避雷规则保留 |

水下角色头上按剩余单位显示0–4个绿色圆点。船长剩余单位由health/maxHealth换算，潜水员由容量减diverBites换算。diverBites仍保留float序列化类型以兼容旧半单位存档；正常新敌人只造成整数伤害。潜水员原有受击2.8s保护保持。

近战只由GameSession.MeleeAttack成功接纳时发出动画事件并结算伤害；重复输入不重播挥击。内置CD默认0.6s，实际锁定至少持续CrewPresentation.swingSeconds（默认占位0.25s）。替换Animator后，将近战状态标记为Melee（可改meleeStateTag）；该状态normalizedTime<1也会阻止下一击。攻击动画与武器触发事件保留可替换接口。

船上和水下的近战统一使用攻击瞬间朝向的 135° 扇形，有鱼叉时半径 3 米，默认武器半径 1.95 米。空挥也播放扇形动画。水下伤害需要鱼叉，推动货箱使用同一个扇形。联机播放使用房主结算时的朝向。

AquaticCrewCollision是独立实体胶囊，默认crewLayers=第9层；仅与角色碰撞，墙体/绳索地形检测与武器命中Trigger分别处理。鲨、食人鱼、深影继续穿墙，和玩家保持实体接触。攻击既检查原来的中心距离，也检查双方实体接触，防止大体积碰撞体把中心推到咬击阈值外导致永远打不中。

## 雷雨与海鸥

雷雨出现率保持：第2夜必出，第4日起每日以固定种子抽10%；不追踪玩家，落点固定随机。day2为间隔12–18s、预警2s；day2以后每加1日，间隔上下限各减0.5s，预警减0.05s。公式：min=max(6,12−0.5×max(0,day−2))；max=max(10,18−0.5×max(0,day−2))；warning=max(1.2,2−0.05×max(0,day−2))。原有预警结束后开始抽下一次等待的顺序保持。公开字段位于GameTuning，当前派生值通过GameSession.LightningInterval/LightningWarningSeconds查看。

海鸥全天刷新。白昼和黄昏分别按基础夜晚频率的60%和80%推进同一倒计时，切换时段时延续已累计的进度。第1–3天白昼约25秒一波，黄昏约18.75秒一波，夜晚基础间隔15秒。从第4天起基础间隔每天减1秒，第8天降至10秒。有电的T2探照灯开启时，夜晚刷新频率另减40%。

每波最多3只。首日2只的概率为20%，3只的概率为10%，其余情况为1只。此后2只和3只的概率每天各加1个百分点，分别封顶50%和25%。同一波里的海鸥交替从左右两侧的不同位置出现。可通过 `BirdExtraChances` 和 `BirdWaveCount` 查看和测试。

普通海鸥有 1 点耐久，变异海鸥有 2 点。鱼叉对海鸥固定造成 1 点伤害，渔枪固定造成 2 点伤害。对应参数为 `GameSession.birdHarpoonDamage` 和 `GameSession.birdSpeargunDamage`。

首日普通海鸥有25%概率冲向甲板上的玩家，变异海鸥有50%。每只出场时独立抽取，从第2天起两种概率每天各加1个百分点。普通海鸥第16天达到40%上限，变异海鸥第21天达到70%上限。命中可打断当前设备操作、掌舵或救助，玩家承伤次数保持原值。目标进舱、下水或失能后，海鸥可改选另一名甲板船员。没有有效目标或抽中攻击船体时，海鸥攻击船体。被打断会关闭设备和QTE界面，已经付材料的自动制作和修船继续进行。海鸥的攻击选择和角色目标随存档保存。

## 交互与存档修复

- 制作台只列普通制作作业，维修台只列修船作业；可由任一船员在对应设备接管校准。CraftQteAtStation再次校验作业所属设备，残留ID不能跨设备提交。关闭设备重置选中ID、方向边沿、节奏反馈、维修/钓鱼及旧按钮视图；自动制作本身不取消。
- 遗失背包是精确内容货箱，显示“遗失物资 数量/容量”及当前改绑的采集挂绳/互动存入提示；挂绳后由绞盘回收。isLostCargo用于显示，persistAcrossDays用于生命周期，不能和每日普通资源一起删除。
- 每日重建保留未消费的挂绳货箱及遗失货箱；原位置与新墙重叠时移至最近的可进入房间，内容不变。丢弃地形索引、重建绳路径，避免新墙或旧折线卡死。两标记和准确内容均随存档恢复；已交付货箱不保留。
- 暂停/失败/设置/改绑分别使用排序100/110/120/130的独立Canvas；船位置缩略指示排序3，因此不会盖住ESC菜单。
- T3绞盘无电时保留手动校准；电动回收离开面板仍继续。所有水下船员与挂绳货箱按目标数均分效率；绳路径仍按墙折返并允许绞盘破坏阻路活板门。动态敌人不作为绳索路线墙，也不应把授权救援永久堵住。

## 开发迁移与复测

已有工程在Gameplay编辑模式执行LifeLine/Balance/Apply Survival Balance (Preserve Custom Values)，只替换明确的旧默认数值，保留人为自定义参数；保存场景，再用Documentation/Export Current Tuning导出02。源文件同步本身不覆盖已序列化SO或场景。

存档新增balanceVersion与routeDistance、独立高效燃油机状态、货箱保留/失物标记和鸟攻击目标。旧90m航线读档保持相对航程、保留背包和材料；水下船员按船位增量移动，地图资源/敌人按原海区偏移，清除过时折点后重算净空。旧半单位累计伤害乘2，新存档不重复迁移；原始存档对象不会被就地更改。正常船长船上局部坐标不随航线拉伸。
