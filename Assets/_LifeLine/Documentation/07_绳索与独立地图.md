# 碰撞绳索、货箱吊运与独立地图

更新：2026-11-17。本文覆盖旧文档中直线绳长和仅通过相机隐藏船舱的说明。

## 回收与碰撞

`DiverRope` 使用 Unity 3D 胶囊扫掠查询实际障碍。绳路为锚点、若干墙角接触点、目标；受力方向指向目标身前的最后一个接触点。收绳沿折线路径移动，绕过墙角后释放接触点，恢复直线。潜水员和货箱均执行碰撞扫掠，不会穿墙传送到船底。用于规划的净空取角色胶囊尺寸，避免绳能穿过但角色过不去。

绳长等级为 28 / 44 / 54 / 74 / 100m，但限长、船体水平移动约束和回收进度使用**整条折线长度**。绕建筑会消耗额外长度；旧地图检查中的直线距离只表示几何范围，不代表所有房间的绕墙路线均能在100m内到达。最深迷宫的实际探索范围仍需完整双人试玩平衡。

船长操作绞盘及获准启动的电动绞盘在正向回收时，检查当前受力线段和紧邻墙角的捷径；挡住回收的关闭活板门可被直接破坏。普通游泳、限长与单纯绘制绳子不会破坏门。普通墙体不能被破坏，也不能隔墙选择后面的门。破坏不消耗材料、不产出材料，门的视觉及碰撞关闭，不能再次互动；本日存档保留 destroyed 状态，下一日新地图重新生成门。

主要公开参数：collisionSkin=.035m、cornerMargin=.065m、contactArrivalDistance=.025m、maximumContacts=128、maximumPullSegments=128、maximumSearchNodes=512、maximumSearchCasts=18000、maximumDetourRatio=6、minimumSearchReach=24m。实际以02导出和 Inspector 为准。它是接触路径和扫掠约束，不模拟可缠绕角色的刚体软绳。

## 弯折性能预算

路由更新按锚点、终点、帧号与几何版本缓存；同帧绘制、限长、船移、绞盘复用同一查询结果。复杂寻路将墙角扩展、相邻障碍探索、闭合节点补链全部排队分帧，默认frameBudgetMilliseconds=1.5（编辑模式完整求解，不分帧）。无路的静止目标重试间隔failedSearchRetrySeconds=.18；开关/破坏活板门和重建地图会NotifyGeometryChanged立即失效缓存。已求得路线仍做实际扫掠，暂停搜索不穿墙回收；绳接近上限或确无路时限制继续运动。

公开诊断totalQueries、routeCacheHits、detourSearches、SearchPending；复杂生成废墟8个终点实测单次更新最高1.556ms，218次分帧调用累计321.21ms，同帧额外1744次调用均复用缓存。旧实现曾出现单次82.1ms的集中搜索。不同机器/关卡需再测，不把工作分帧当作路线必可达的保证。保留512节点/18000扫掠安全上限。

## 货箱操作

1. 非空背包在空箱/未挂载箱旁按 Enter，每次将背包末尾一件放入箱内，最多3件。
2. 非空箱旁按住潜水员采集键（默认1）1秒完成挂载；背包T3的1.25倍采集速度同样生效。空箱不能挂载。
3. 挂载立刻显示独立吊索。启动绞盘同时牵引水下潜水员和所有有效挂载箱；单、双信号仅通知船长，不切换独占目标；电动三连信号自动启动同一批目标的回收。
4. 船长在绞盘处启动回收。货箱沿碰撞绳路移动，到达船底才按 contents 实际材料逐件入库。没有随机额外奖励；潜水员也沿自己的绳路同时回收。

潜水员绳与货箱绳共用 `DiverLifelineView`：cargo为空画潜水员，指定箱子则画该箱吊索。每箱的 LootPickup.lifeline 都是独立的物理与显示路径；Session.cargoRope 只兼容指向第一件货物，不控制牵引优先级。读档时 attached 箱子重新建立可见吊索，已入库箱子的绳随箱隐藏。物资标签与挂载表现可以单独换美术。

船长视角另有 `shipLead` 出绳段，从真实 `winchAttachment` 接到船底锚点，归属船体子树；右侧绳头接水下缩略船的WinchPoint。两处表现读取同一个绞盘状态，收人、吊货时出现，目标全部回收后关闭。不会将1000m地图偏移画成跨图长绳。

## 地图隔离与坐标同步

`GameMapPartition` 在运行时创建独立的 ShipMap、UnderwaterMap additive 场景。船和船舱的物理原点默认 (0,1000,0)，水下原点默认 (0,0,0)；两者通过 GameSession 的位置/电量/绞盘状态及坐标转换同步。这里使用默认共享物理世界，通过空间距离和层隔离；不是两个独立 LocalPhysicsScene。

作者只维护一个 Gameplay 场景，序列化原点偏移以防重复加1000m；运行时归属对应场景。船员下水和登船时转移归属。`ShipPoint` 是船上实际坐标，`WaterShipPoint` / `BoatAnchor` 是水下对应坐标；跨图使用 `ShipToWaterPoint` / `WaterToShipPoint`，禁止直接拿船舱Y坐标计算水深或敌人距离。

水下只创建无碰撞、无站点的 `UnderwaterShipProxy`，船体宽3.4m；它不复制船舱。绞盘几何、公开 `WinchPoint` 和吊索首端使用同一个连接点，原船绞盘横向偏移以 .14 缩放。原船可移动时，缩略船和绳头跟随更新。水面船离开视窗后提供58×30px的小船方位图标，默认视窗高度.78。水下相机 `underwaterSurfaceHeadroom=4.5`，给缩略船留出显示空间；绳默认 z=-1.7，避免被缩略船遮住。

几何与表现替换接口：Proxy.visualRoot / winchVisual、DiverLifelineView.rope / ropeMaterial / width / ropeColor / cargoAttachmentLocal，以及各组件public参数。更换模型时将 winchVisual 与 WinchPoint 对齐，保留相应剔除层。水下代理层14；真实船体仍在船上层，不参与水下相机碰撞。

## 存档与迁移

新存档 coordinateVersion=1；船体、海鸟和船上投射物用规范化的逻辑坐标保存，加载时映射至当前船上原点。旧 coordinateVersion=0 的共享空间存档自动转换，潜水员/水下敌人/嵌在敌人身上的鱼枪不会误加1000m。潜水员接触点保存到 diverRopeContacts，每个挂载箱独立保存 PickupSaveState.ropeContacts；旧 cargoRopeContacts 保留用于旧档第一件货物的兼容。恢复后验证实际障碍并重建显示。

已有作者场景使用 `LifeLine/Migration/Separate Ship And Water Maps` 显式升级。命令要求先保存当前改动，会备份原场景到 Documentation/SceneBackups，保留配方、预制体与手工内容，添加地图组件、绳路和缩略船，再保存并重新导出02。不要为升级而强制重建整个Gameplay。

最新验证结果见00。绳路、地图、货箱操作仍需按03进行完整双人航程试玩。

## 多目标牵引效率

N=未登船潜水员数量（0或1）+已挂载、未入库且激活的货箱数量。每个目标获得基础牵引量的1/N：潜水员+1箱，各50%；潜水员+2箱，各1/3；只有1箱时为100%。空箱、未挂载、已入库、禁用对象不计入。

被动速度、电动附加速度、QTE成功牵引距离和失败回滑距离都使用同一比例。比例在每次牵引开始时计算；某目标在本次到达后，其余目标从下一次牵引起分得新的效率，不把本次剩余量再分配。障碍阻挡的挂载物仍计入N；不能通过卡住一箱给其他目标免费提速。所有目标都走各自折线路径；关闭活板门仍可在正向回收时破坏，普通墙体不能穿越。

潜水员先上船时仅卸下其背包并恢复船上状态，不中断剩余货箱回收；所有目标完成后才清除电动自动授权。船体移动同时受所有挂绳路线最大长度约束。绞盘面板显示“N × 每目标效率”、综合剩余路长进度，QTE反馈显示每目标实际距离。每个箱子到达船底独立按实际contents入库一次。

## 船舱跳跃与摄像机

实际第2日雷雨场景中，一人甲板、一人舱内跳起时，同屏焦点进入甲板碰撞体；旧设置将相机Z从-24推到约-1.321，修复后保持-24。船体为侧面剖视图，船舱地板/顶棚所在ShipSolidLayer（默认10）不参与两台官方Cinemachine的Deoccluder和Decollider遮挡查询，避免剖视结构将镜头推入几何表现平面。角色与船舱的物理碰撞保留，World层废墟仍参与官方摄像机防碰撞。船舱跳跃不改变船体子物体姿态。

雷击露天判定使用角色在船体局部坐标是否达到deckY（默认0），替代原来的-2m阈值；舱内跳跃最高点不会被误判为在甲板。甲板雷击、5秒救助和双人倒地规则保持现有机制。
