# 18 · 建筑货箱与藏匿点随机分布

更新日期：2026-11-18。本篇覆盖早期文档中“每栋固定两个入口／奖励货箱、一个左上角藏匿点”的描述。物资种类权重、普通物资数量、洞穴与电鳗事件不变。

## 数量与建筑分类

| 建筑 | 默认房间数 | 藏匿点／栋 | 空货箱／栋 |
| --- | --- | --- | --- |
| 小建筑 | 5×3＝15格 | 2–3 | 1–2 |
| 大建筑 | 7×4＝28格、9×5＝45格 | 3–5 | 2–4 |

默认以24个房间为大建筑门槛，按实际建筑尺寸分类，不按浅滩／城区／深水区分类。原有建筑和新增航线覆盖建筑全部采用本规则；默认地图有11栋小建筑、15栋大建筑。洞穴使用单独的电鳗／守卫布局，不增加普通货箱或藏匿点。

数量在各自区间内以整数等概率抽取。正常默认尺寸有足够候选格，保证满足表内数量。开发者自行把尺寸缩小或数量改得超出候选房间时，最终数量受可用房间限制。

## 位置抽取

1. 从入口遍历连通图，将全部可到达、满足50m可收集深度和货箱底部余量的房间加入候选。
2. 使用当天种子与建筑身份派生的独立随机流，打乱候选格；数量与位置不再绑定原入口格、奖励格或左上角格。
3. 首个点随机，后续点优先选择距离已选点较远的房间；等距离时使用已打乱顺序。藏匿点和货箱使用不同房间，同一类也不重复占格。
4. 点位在房间内部偏移，默认货箱`(.72,-.20,-.12)m`、藏匿点`(-.65,-.08,0)m`，为通道和普通物资留出空间。货箱是触发器，藏匿占位模型不阻挡玩家。

独立随机流不改变原有迷宫、普通物资／鱼获、活板门、过滤器、洞穴或敌人候选点的随机结果与ID。同一天、相同基础种子和配置会得到相同分布；下一天重新抽取。分散使用房间格的曼哈顿距离，不能理解为各点之间存在直线通道；玩家仍需沿迷宫通道移动。

## 互动与保存

货箱保持空箱、3格容量。玩家自行将背包物品装入并挂绳，绞盘同时回收挂载物和水下船员，仍按目标数分配效率。藏匿仍按互动键进入／退出，隐藏模型、锁定移动、免受索敌和攻击，继续正常耗氧。

保存时记录全部藏匿点的位置、建筑／房间编号及互动范围；同日读取恢复快照，不重新抽取，藏匿中的角色仍在原处。货箱继续保存内容、挂载、回收／消耗状态、位置与绕障绳路。

旧普通货箱ID保留；新抽取不需要的旧货箱以已消耗、停用记录保留，开发者查看`world.pickups`总数时必须排除`consumed`或未激活对象，才能得到实际货箱数。这些占位记录不会显示、收集或被绞盘选中。新增加的第3／4个箱子使用独立稳定ID，不挤占普通物资的编号。

读取旧存档时旧货箱的位置与内容照常恢复；未存在于旧存档的新增货箱当日不额外补发，下一日按新区间生成。旧档没有藏匿点快照时使用新分布；若角色正在旧点位藏匿，必要时将同栋一个新点移回原点，以保留藏匿状态，不额外增加该栋数量。之后再次保存即有完整快照。

## 调参和代码位置

Gameplay场景的`WorldGenerator`公开字段：

| 字段 | 默认值 |
| --- | --- |
| `largeBuildingMinimumRooms` | 24 |
| `smallBuildingHideCount`／`largeBuildingHideCount` | (2,3)／(3,5)，区间含两端 |
| `smallBuildingCrateCount`／`largeBuildingCrateCount` | (1,2)／(2,4)，区间含两端 |
| `buildingCrateOffset`／`buildingHideOffset` | (.72,-.20,-.12)／(-.65,-.08,0)m |
| `maximumLootDepth` | 50m |

`cratesPerZone=2`现在用于保留原有货箱ID和编号顺序，不再控制玩家实际可见箱数。调整生成数量请修改上表区间。正常游戏中不需要编辑隐藏记录。

生成实现位于`Scripts/Runtime/World/WorldGeneratorBuildingFeatures.cs`；藏匿组件`UnderwaterHideSpot`增加`mazeIndex`／`mazeCell`便于检查；快照与旧档兼容位于`Scripts/Runtime/Persistence/WorldHideSpotPersistence.cs`和`GameSessionPersistence.cs`。全部是可编辑源码和public参数，无新增强制美术资源或设备预制体。
