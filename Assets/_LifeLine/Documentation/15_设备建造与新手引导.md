# 15 · 设备建造与新手引导

更新日期：2026-11-18。本文记录本轮实现后的规则、默认数值、开发入口和存档兼容边界。此前未变动的完整生存数值见 `13_生存平衡与交互修复.md`，绞盘 T4 与建筑通道规则见 `14_绞盘T4与建筑多出口.md`。本轮规则与旧文档冲突时，以本文及项目当前 SO、场景配置为准。

同日后续调整见[16_拾取救助与昼夜优化.md](16_拾取救助与昼夜优化.md)：船长E拾取／固定4格、潜水员Enter藏匿、绞回倒地后需4秒扶起、5秒首次提醒、短过场与地图／昼夜开销优化。本篇下方109/109、47/47和构建记录保留为设备建造批次历史结果，不代表后续批次已验证。

## 1. 新游戏开局

| 项目 | 默认值与行为 | 配置入口 |
| --- | --- | --- |
| 当前船体耐久 | 70 | `GameTuning.initialHull` |
| 基础耐久上限 | 100，开局显示 70 / 100 | `GameTuning.baseHull`；不是把上限改成 70 |
| 当前电力 | 0% | `GameTuning.initialPower` |
| 引擎状态 | 未修复；修复前不能主动航行 | `GameSession.engineRepaired`、`ShipMotor` 航行检查 |
| 引擎首次维修消耗 | 2 铁板；授权后完成原有 4 个故障清理、匹配维修流程 | `GameTuning.firstEngineRepairPlates`、`engineFaultCount` |
| 之后引擎再次损坏 | 沿用原有规则，只需动手维修，不重复消耗首次修复材料 | `GameSession.engineEverRepaired` |
| 初始可用核心站点 | 制作台、设备总控、船舵、绞盘、潜水准备、电路和引擎 | 相应 `StationAnchor` |

修复引擎不会凭空发电：实际航行仍需有电力。玩家先下水打捞材料，再制造手摇发电机补充动力；保留本地双人合作和后续联机的权威会话接口。

## 2. 六类设备先解锁，再出现

新游戏中下列设备的整个交互根节点默认隐藏，包含几何占位图形与 `StationAnchor`；未解锁时不能通过邻近互动、残留面板或开发完成按钮绕过。达成条件后自动出现，不再要求摆放道具。

| 设备 | 出现条件 | 权威状态 |
| --- | --- | --- |
| 垂钓点 | 在制作台完成鱼竿配方 | `hasRod` |
| 探照灯 | 在总控完成第一次探照灯建造升级 | `UpgradeKind.Searchlight` 等级 > 0 |
| 炮塔 | 在总控完成原有炮塔建造 | `turretInstalled` |
| 发电机 | 在制作台完成手摇发电机配方 | `generatorInstalled` |
| 船体维修台 | 在制作台完成船体维修台配方 | `repairBenchInstalled` |
| 海水过滤器 | 在城区中层水下打捞到设备 | `filterInstalled` |

炮塔原有建造材料保持为 3 木板、3 铁板、1 纤维束；T2 升级保持为 1 铁板、3 纤维束、1 木板。本轮调整设备出现时机，原有炮塔攻击优先级、双目标和耗电逻辑保持不变。

设备是否存在与是否启用分别记录。例如过滤器打捞后可看见并互动，但 `filterRepaired` 为真之前不提供增益；探照灯出现后仍需打开 `searchlightOn` 才影响视野。

## 3. 制作配方与消耗

当前项目共15个独立配方SO。配方由 `CraftingManager` 统一读取 `RecipeDefinition` SO，费用不放在 UI 或占位美术脚本里。默认制作台时间仍为 40 / 30 / 20 / 15 秒，QTE 可加速；设备在作业完成后才解锁，单纯开始制造不会提前出现。

| 配方 | 材料消耗 | 完成结果 |
| --- | --- | --- |
| 手摇发电机 | 2 金属 + 2 木材 + 1 纤维 | 解锁船舱发电机；这里全部是原材料，不是铁板、木板或纤维束 |
| 船体维修台 | 1 木材 + 1 金属 | 解锁船体维修与快速维修入口 |
| 鱼叉 | 2 铁板 | 获得近战鱼叉，按原有装备规则替代船桨 |
| 射矛枪／渔枪 | 2 铁板 + 2 纤维束 + 1 把鱼叉 | 消耗已有鱼叉并获得独立发射、召回的射矛枪 |

射矛枪的鱼叉依赖在作业开始时检查并原子消耗；材料不足时不能先扣掉鱼叉。取消作业不会返还已投入资源，也不返还鱼叉。射矛枪继续使用独立发射键，不把它装进近战槽；鱼叉已作为材料消耗后，近战按实际持有状态回退。

设备默认配方资产位于：

- `Assets/_LifeLine/Data/Recipes/14_Generator.asset`，`id/toolId = generator`。
- `Assets/_LifeLine/Data/Recipes/15_RepairBench.asset`，`id/toolId = repair-bench`。
- 既有 `id = harpoon`、`id = speargun` 配方分别调整资源费用与鱼叉消耗。

开发者可直接修改 SO 的 `cost`、`output`、`toolId`、`requiredToolIds`、`consumedToolIds`、`craftTimeMultiplier`、图标及完成视觉引用。`requiredToolIds` 只检查拥有关系，`consumedToolIds` 才表示需要消耗的工具，避免把工具前置条件与资源数量混为一谈。

## 4. 城区中层过滤器打捞

| 项目 | 默认数值／规则 | 公共配置 |
| --- | --- | --- |
| 出现海域 | 城区水域 | 城区现有海域边界、建筑房间 |
| 出现深度 | 水面以下 20–35m | `WorldGenerator.filterSalvageDepths` |
| 出现概率 | 每日地图生成时独立 30% 判定，不是每个房间各判定一次 | `filterSalvageChance = .30` |
| 随机性 | 使用每日地图种子的独立随机流；不扰动原有地形、资源、鱼获、深层洞穴和电鳗事件的随机序列 | `RollFilterSalvage(daySeed, chance)` |
| 打捞方式 | 靠近后持续按收集键，默认 3 秒 | `filterSalvageSeconds`、`FilterSalvage.salvageSeconds` |
| 背包 | 不占背包格，背包满也可打捞；完成后直接安装到船上 | `FilterSalvage.TryAcquire` |
| 食人鱼看守 | 默认至少安排 2 个近处看守点，与城区食人鱼共用最多 6 只上限 | `filterGuardMinimum = 2`、`GameTuning.maximumPiranhas = 6` |
| 看守范围 | 设备周围默认 6m 内的可用房间点，避免直接压在设备上 | `filterGuardRadius = 6` |
| 唯一性 | 获取后后续每日地图不再生成第二个过滤器；存读档保留已获取状态 | `filterInstalled` |
| 修复成本 | 安装后还需消耗 2 铁板并完成管道连接维修 | `GameSession.filterRepairCost` |

看守数量服从食人鱼总上限；开发者把总上限设为 0 或低于 2 时，不能为了看守而突破这个调试上限。地图缺少符合海域、深度的可用房间时也不把设备硬塞进不可达墙体。

未取得的过滤器是有独立标识的世界设备，存读档后恢复其打捞行为和提示，而不是变成一块金属。外形由 `WorldGenerator.filterSalvageVisualPrefab` 替换；默认用双罐体、管线和底座几何体区分普通资源。已获取设备读取旧地图记录时会隐藏，避免重复领取。

## 5. 过滤器修复后的增益范围

过滤器提供两个独立的 1.2 倍系数：

- 船长、潜水员的水下移动速度 × 1.2；不加成船上走动，不加成船体航速。
- 船员在船上主动操作当前设备时，相关交互时间轴 × 1.2。等价所需时间除以 1.2，缩短约 16.67%，不是直接减掉 20% 时间。

`GameSession.filterMoveMultiplier = 1.2` 控制水下移动，`filterInteractionMultiplier = 1.2` 控制船上设备效率。`DeckInteractionEfficiency` 和 `GetDeviceInteractionEfficiency(actor)` 是统一读取接口；未修好、操作者不在船上或处于失能状态时不应用设备增益。

| 设备场景 | 增益表现 |
| --- | --- |
| 制作／修船 | 船员正在对应站点操作的当前作业时间轴加速；离开后自动作业恢复基础速度，不把共享队列中的其他作业一并加速 |
| 绞盘 | 当前手动操作时圆形 QTE 与回收时间轴加速；离开面板的自动回收不额外获得“有人操作”的过滤器增益 |
| 手摇发电机 | 一次有效摇柄间隔由 3 秒变成 2.5 秒，每次仍发 1% 电力；升级燃油发电机后仍保留手摇 |
| 钓鱼 | 只加快有效操作带来的成功进度，不提高鱼的滑动速度，不因为设备增益反而提高追鱼难度 |
| 电路、引擎、管道维修 | 对应当前交互的时间型步骤按设备效率推进；仍需匹配正确线路、故障或管道 |

引擎修复、设备建造、资源花费、配方队列容量和各站点隔离仍执行正常规则。效率系数不会把“打开一个面板”变成自动完成其他设备。

## 6. 探照灯建造与分级

为表达“初始没有设备”，探照灯等级改为以下三种状态：

| 等级 | 当前含义 | 费用 |
| --- | --- | --- |
| 0 | 未建造；设备隐藏 | 无 |
| T1 | 设备出现；打开后提供较大夜间水下视野 | 2 木板 + 2 铁板 |
| T2 | 打开后提供接近白天的完整夜间水下视野，并使夜间海鸥刷新减少 40% | 再消耗 2 木板 + 2 铁板 |

不开灯时仍保持近身夜视；开灯也会让敌对水生生物从夜间较小索敌范围恢复白天范围。总控只展示下一次升级的效果与费用，满级禁用。旧存档的原始等级 0 / 1 在迁移后对应新等级 1 / 2，避免拿走以前已经存在的基础探照灯。

## 7. 绞盘圆形 QTE 动态判定区

绿色判定区不再固定在圆的一处，可出现在整圈任意角度。以下三种情况都会刷新中心位置：转满一圈、一次输入判定成功、一次输入判定失败。刷新后保证窗口相对上次有可见位置变化。

| 参数 | 默认值与含义 |
| --- | --- |
| 一圈基础时间 | `GameTuning.winchCycle = 1.7s` |
| 判定区原始宽度 | `winchOriginalWidth = .1`，占圆周 10% |
| 基础宽度加成 | `winchBaseBonus = .1`，最终基础宽度 .11 圈 |
| T2 追加宽度加成 | `winchT2Bonus = .1`，T2 起最终宽度 .12 圈 |
| 最短接受输入间隔 | `GameSession.winchMinimumInputInterval = .18s` |
| 失败卡顿 | `.3s`，保留失败减进度及吸引敌人的逻辑 |
| 成功基础回收量 | `winchGoodDistance = 1.78m`，仍受挂载数量与升级系数影响 |
| 失败基础滑退量 | `winchBadDistance = .89m`，仍按挂载数量分担 |
| 空闲慢速回收 | `winchPassiveSpeed = .14m/s` |

判定用 `CircularQteDistance(a, b)` 计算最短环形距离；中心在 .99、指针在 .01 时应按相距 .02 圈处理，绿色区跨越顶部 0 / 1 接缝也有效。

`winchTargetCenter`、`winchCenterInitialized`、`winchCueCooldown` 是运行时状态。`ResetWinchTarget()` 初始化并刷新窗口；UI 通过 `WinchQteCenter`、`WinchQteWidth` 读取，不另存一套判定值。T4 维持 100m 绳长、正向拉回效率 +20%，手动校准及无电手动回收仍保留；新目标位置规则没有改变绳索碰撞、定滑轮折线与挂载分担。

## 8. 主菜单、渐入与船长氧气

主菜单通过 `GameSaveManager.HasValidSave` 完成实际读取和有效性检查，再调用 `MainMenuController.SetContinueAvailable`。没有有效存档时隐藏“继续游戏”的整个按钮对象；存在文件但损坏、版本或内容无效时同样隐藏，而不是只把按钮变灰。

“开始游戏”调用 `RequestStartGame()`，先设置新游戏请求，在异步载入 Gameplay的同时淡出菜单，允许场景激活并等待初始化／一帧后淡入。后续16将`newGameFadeOutSeconds`默认设为.1秒、`newGameFadeSeconds`设为.2秒；使用未缩放时间，不额外固定黑停。实际载入还受地图初始化用时影响。`IsStartingGame` 和 `SceneFadeTransition.IsTransitioning` 防止重复启动；跨场景遮罩位于排序10000的独立Canvas，在过场期间拦截UI点击，结束后销毁。可替换`SceneFadeTransition.image`以及动画表现，不用改存档加载逻辑。

潜水员原有右侧氧气条继续专用潜水员数值，不再混入船长氧气。船长在船上时隐藏其额外氧气 UI，入水后才显示在左半屏船体耐久文本下方，清楚显示当前秒数／最大秒数；船长固定基础氧气仍是 50 秒，不接受潜水员氧气升级。

默认布局使用 Canvas 归一化锚点：

| 区域 | 最小锚点 | 最大锚点 |
| --- | --- | --- |
| 既有耐久等数值条 | Y = .799 附近 | Y = .823 附近 |
| 船长氧气 | (.02, .753) | (.25, .797) |
| 主教程透明文本框 | (.02, .56) | (.49, .744) |
| 首次事件提醒透明框 | (.02, .40) | (.49, .55) |

这三块新增 UI 不覆盖右上角主线，且彼此不重叠。进入暂停／结算时隐藏；设备面板打开时默认暂时隐藏教学文字，避免遮盖设备按钮与 QTE，事件提醒的阅读倒计时也同时停住。船长水下氧气仍按当前玩法状态独立显示。

## 9. 新手引导与首次事件提醒

新游戏显示八步合作教程，不暂停游戏、不接管输入，不更改 `QuestText`／右上主线目标：

1. 船长在制作台尝试制造 1 木板，成功创建作业就记为尝试，不要求原地等到完成。
2. 船长打开设备总控查看升级。
3. 潜水员在潜水准备台下水，提醒氧气、背包和绳长。
4. 潜水员收集到水下物资。
5. 向货箱存入至少 1 件物品，说明每箱 3 格。
6. 把有货物的货箱挂绳，说明挂载越多回收越慢。
7. 进入藏匿处，说明再次互动退出、不能移动、不会被索敌和攻击，并提醒更深处有敌对水生生物。
8. 船长操作绞盘接回潜水员，完成基础引导。

基础教程以真实动作和权威状态推进，不按等待时间自动跳步。玩家提前做过后续动作会保留观察位，轮到那一步时不会要求重复表演；实际互动结果 hook 与状态轮询互为补充。

另外有独立队列，每条只提醒一次，不挤掉主教程或主线：

- 首次出现海鸥：海鸥会伤船、降低耐久，可用近战赶走；部分会打断船员操作。
- 任一船员首次夜潜：需要建造并开启探照灯改善视野，灯光也会扩大敌对水生生物索敌范围。
- 首次雷雨夜：离开落点预警区域，同伴倒地需持续互动4秒扶起，两人都倒下会失败。

单条提醒默认展示5秒，由`TutorialProgress.noticeSeconds`调整；多条同时触发时排队，暂停或设备面板遮住提醒时不扣阅读时间。`DismissNotice()`可供以后替换UI的关闭按钮使用。提醒结束不等于主教程完成。已有场景旧16秒值的显式迁移入口见16。

## 10. 开发测试工具

仅编辑器或 Development Build 包含 F8 测试工具。F8 打开控制台后新增：

- “跳过当前设备 QTE”：持续完成当前已打开、已解锁设备中的有效交互。
- “立即完成当前互动”：只执行一次。

制作／修船只完成已经支付材料并创建的对应站点作业；引擎、电路、过滤器先走正常维修授权与材料消耗；未建造设备不能借此出现。绞盘可直接接回当前目标，发电执行有效摇柄，钓鱼只完成已开始的钓鱼交互。不会凭空补齐材料、免费建造所有设备或穿过设备解锁检查。

测试动作使用 `LifeLine/developer-test.json` 隔离存档，不覆盖正常自动／手动存档槽。核心入口是 `GameSession.DeveloperCompleteInteraction(panel, actor, hud)`、`DeveloperTestTools.CompleteOpenInteractions()` 与 `skipInteractionQte`。相关代码集中在 `Runtime/Development` 并以编译条件隔离，后续可整体删除或替换工具 UI。
