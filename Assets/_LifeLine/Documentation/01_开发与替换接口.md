# 开发结构、导入与资源替换

当前源码实现 Unity 6 的本地双人游戏，使用 3D 物理的 XY 横版视角、新版 Input System 和 Cinemachine 6.6.0。主菜单提供本地双人、设置与退出；设置包含语言、船上同屏/分屏和角色换绑。没有已经接通的在线会话、单人助手或无尽入口。构建、测试与实际播放的验证范围见 `03_玩法机制与测试清单.md`；联网预留边界见 `04_P2P接口与后续接入.md`。

## 文件夹与构建入口

开发源文件先存放在本仓库 `UnityGameStaging/`。实际 Unity 工程把 `Runtime/Editor` 分别放在 `Assets/_LifeLine/Scripts/Runtime` 和 `Scripts/Editor`，其余 Tests、Shaders、Documentation 对应放在 `Assets/_LifeLine/` 下的同名目录。下表 Runtime/Editor 是源码内相对目录，实际工程前缀为 Scripts。`IMPLEMENTATION_CONTRACT.md` 是协作说明，不作为游戏脚本导入。

| 目录 | 内容与职责 |
| --- | --- |
| `Runtime/Core` | 枚举、命令、站点、配方与 `GameTuning` 数据定义 |
| `Runtime/Gameplay` | `GameSession` 权威共享状态、背包、维修、救援、天气、敌人与武器；独立 `CraftingManager` 实际拥有制作流程 |
| `Runtime/Input` | 双角色 action map、运行时克隆、换绑与持久化 |
| `Runtime/Characters` | `CrewActor`、`ShipMotor`、梯子舱口；唯一的角色与船舶物理移动入口 |
| `Runtime/Presentation` | 可选 Animator 与音效/VFX 接收接口；夜间可见性视图 |
| `Runtime/World` | 种子迷宫、真实碰撞墙、资源、货箱及收集 |
| `Runtime/Cameras` | Cinemachine 共享/分屏相机、限界与遮挡处理 |
| `Runtime/UI` | 可编辑 UGUI 主菜单、HUD、站点、小游戏和键位设置 |
| `Runtime/Localization` | 中英文可编辑词表、系统语种/偏好、显示绑定与漏译诊断 |
| `Runtime/Networking` | 传输、身份、输入与快照 DTO；尚无联网传输实现 |
| `Runtime/Persistence` | 版本化存档DTO、数据验证、文件原子覆盖与场景启动管理；Session状态捕获/恢复在Gameplay的partial文件中 |
| `Editor` | 显式构建与文档导出工具，正常运行不自动重建场景 |
| `Tests/EditMode` | 配方/换绑数据、迁移、远端命令语义、本地化与完整默认词条覆盖 |
| `Tests/PlayMode` | 真实 Input System action 回调、船体携带/耗电、绞盘碰撞、暂停与Cinemachine遮挡恢复 |
| `Data/Tuning`、`Data/Recipes`、`Data/Localization` | 可直接在 Inspector 调整的规则、逐配方SO与双语词表 |
| `Prefabs`、`Materials` | 可替换预制体、共享材质 |

菜单 `LifeLine/Create First Playable (Preserve Existing)` 调用 `GameProjectBuilder.Build(false)`。它建立缺失的资产与 `Scenes/MainMenu.unity`、`Scenes/Gameplay.unity`，将两场景加入 Build Settings，并打开主菜单。`PrefabLibraryBuilder.Build()` 返回可复用的场景依赖库；`InputAssetBuilder.CreateOrUpdateAsset()` 建立输入资产。

默认已有场景、Prefab、材质、调参资产和配方均保留，不在进入 Play 时重建。`Build(true)` 只显式重建生成场景，仍保留已有库资产。构建命令会设置 Build Settings 的两场景及产品名、默认窗口尺寸等项目选项；这些项目设置与场景/资产保留规则不同。已有同编号 Layer 名称会保留并输出提示。

## 首次导入与已有工程更新

1. 退出 Play，将 staging 的 Runtime/Editor 同步到 `Assets/_LifeLine/Scripts/Runtime` 与 `Scripts/Editor`；Tests、Documentation、Shaders 同步到 `_LifeLine/` 下同名目录。沿用现有位置并保留 `.meta`，避免把同一份 C# 再复制到另一目录形成重复类型。不要删除已手工调整的 Prefab、材质和数据资产。
2. 等待 Unity 编译完成，确认使用 `LifeLine.Runtime`、`LifeLine.Editor`、`LifeLine.Tests.EditMode` 与 `LifeLine.Tests.PlayMode` 程序集。依赖是项目中已安装的 Input System、Cinemachine 与 UGUI；脚本不负责自动安装包。
3. 新工程运行上面的 Preserve Existing 构建菜单。已有工程先查看本轮迁移预览，按下一节处理旧默认值与新配方，再打开现有 Gameplay 核对 Inspector 引用。
4. 用 Test Runner 分别运行 EditMode 和 PlayMode。2026-11-17实际Unity结果为EditMode 53/53、PlayMode 33/33通过，Gameplay规则检查73/73通过；后续修改仍应重跑相应检查。输入/物理测试必须在PlayMode运行，本地化与数字键迁移及存档数据往返在EditMode运行。之后从MainMenu检查完整双人流程、窗口布局、语言与镜头设置；具体已验证范围和人工清单见03，不以静态编译代替实际运行。
5. 参数确认后，在 Gameplay 场景运行 `LifeLine/Documentation/Export Current Tuning`，更新 `02_实际数值参考.md`。该文件从实际资产与场景导出，优先于文档里手写的旧数值。

### 新规则迁移

Preserve Existing 不会把已有 Gameplay 的 `session.recipes` 自动换成新版数组，也不会覆写旧调参。新版快速修补是新增的 `quick-hull` 配方：1 木板恢复 10 船体，`craftTimeMultiplier=.5`；普通配方该值为 1，并在制作台升级后的基础耗时上再乘此值。

`LifeLine/Migration/Preview Current Rules` 只列出计划；`Apply Current Rules (Preserve Custom Values)` 才执行迁移。迁移先备份被修改的数据/场景/Prefab，给已有 Gameplay 追加缺失的快速修补引用，并只识别、替换已知旧默认值：氧气60/90/120/150改为40/70/115/145、baseOxygen 60改40、末档绳长44改74、手摇间隔1改3秒、洞穴/电鳗概率.55/.75改为.05/.05、旧兼容制作耗时30改25、制作台升级成本1木板+1铁板改为2木板；Captain/Diver prefab的waterBottomY仅在仍为-45时改为-54。其他自定义值和配方保留，输出日志供核对。正处于Prefab Mode的角色资产会跳过，保存并关闭后再迁移。已移除且不再引用的旧升级成本数组无需改写。若这些字段本来就有意使用旧数值，请改用 Inspector 手工迁移。

新增字段如背包、潜水服升级、扶起时间及分级制作耗时由最新版脚本提供默认值；已有同名序列化字段以资产实际内容为准。升级后的手摇操作仍保留。迁移前先保存正在编辑的资产与场景；工具会跳过仍为 dirty 的原文件。迁移后应再次导出数值表并运行规则回归。原文件与meta以 `.bak` 形式备份在 `Documentation/MigrationBackups/`，恢复原路径时保留原meta/GUID，并同时还原场景和对应数据；不要把备份当作新资产替换引用。

### 独立制作管理器与配方 SO

每个 `Data/Recipes/*.asset` 都是一份可编辑的 `RecipeDefinition` ScriptableObject，成本、输出和修船效果不写死在 Manager 中；不再额外套一层 RecipeCatalog。`CraftingManager` 是 Gameplay 目录下的独立 MonoBehaviour，与 `GameSession` 放在同一 GameObject，通过公开 `session`、`recipeDefinitions[]` 和 `jobs` 持有依赖与唯一队列。

它实际负责配方查找、解锁和重复验证、原子扣料、入队、耗时/QTE、自动推进与完成产物结算。共享仓库、设备、工具与主线状态仍由关联 session 维护。`GameSession` 的 TryCraft/CraftQte 等入口和 recipes/jobs 仅作兼容转发，不再维护第二套制作规则。Manager 没有自行运行的 Update 时钟，由 session 每次模拟步调用一次，不能再从 UI 或另一个组件重复 Tick。

场景生成器应调用 `session.GetOrCreateCraftingManager()`，再 `manager.SetRecipeDefinitions(library.recipes)`，而不是无条件再 AddComponent。该显式入口会接收旧序列化 recipes/jobs；已有 Manager 的有效引用/队列优先，迁移缓存移交后清空。纯读取 session.recipes/jobs 不会创建组件，保证旧场景迁移 Preview 只读。制作配方替换时，在 Manager 的 Inspector 配置 recipeDefinitions；UI 仍调用统一制作入口。

## 预制体与物理约定

| 实际资产路径（相对 `Assets/_LifeLine/`） | 关键替换边界 |
| --- | --- |
| `Scenes/MainMenu.unity`、`Scenes/Gameplay.unity` | 可编辑的菜单/游戏场景；已有场景由默认构建入口保留 |
| `Input/LifelineControls.inputactions` | 双角色输入资产，实际运行由Reader克隆使用 |
| `Data/Tuning/GameTuning.asset`、`Data/Recipes/*.asset` | 规则调参和逐配方SO；Manager引用配方，不复制成本数据 |
| `Data/Localization/DefaultLocalization.asset` | 可编辑的中英文文案；由两个场景的Manager共同引用 |
| `Prefabs/Characters/Captain.prefab`、`Diver.prefab` | 稳定根含 Rigidbody、CapsuleCollider、输入与角色逻辑；美术在 `VisualRoot` |
| `Prefabs/Ship/Ship.prefab` | Kinematic Rigidbody、船速、甲板/舱底/侧壁、梯子舱口，以及嵌套站点 |
| `Prefabs/Stations/*.prefab` | 当前13种 `StationKind` 各一份；`StationAnchor` 与 `InteractionPoint` 保留，站点装饰不放实体碰撞 |
| `Prefabs/World/Loot.prefab`、`Crate.prefab` | 稳定触发根与 `LootPickup`；货箱内容是真实物品列表 |
| `Prefabs/World/Trapdoor.prefab` | `TrapdoorGate` 与实体 BoxCollider 稳定根；`VisualRoot` 是无Collider的可替换门板 |
| `Prefabs/Enemies/Shark.prefab`、`Bird.prefab`、`Shadow.prefab` | `LifelineEnemy`、触发 Collider、Kinematic Rigidbody；替换 `VisualRoot` |
| `Prefabs/Enemies/Spear.prefab` | `LifelineSpear`；视觉矛头沿本地 +Y，运行时朝飞行/召回方向旋转 |
| `Prefabs/UI/ActionButton.prefab` | UGUI Button、Image、42高 LayoutElement、子 Text、字体组件 |

角色根代表身体中心，默认 Capsule 高1.8米、半径.32米；甲板脚底为Y=0，船舱脚底Y=-4，对应站立中心约.9/-3.1。3D Rigidbody 锁Z与旋转，重力由 `CrewActor` 按 tuning 控制。场景层约定：8 World、9 Crew、10 Ship、11 Pickup、13 Enemy。Cinemachine 的限界形状虽用2D边界组件，角色和场景实体仍使用3D物理。

角色根不挂在船的 Transform 下。`ShipMotor` 每个物理帧只移动船一次，`CrewActor` 在甲板速度里只加一次 `ship.speed`，其中包含环境漂移。不要额外用父级移动、动画根运动或另一个脚本再次携带角色。潜水时只忽略船体碰撞，保留废墟/洞穴碰撞；绞盘经 Sweep 检测安全移动。上船由 session 的绞盘流程调用 `SetOnboard`，潜水员靠近船或按互动不会自行登船。普通回收由船长控制；升级电动设备后的三连信号自动回收是 session 明确验证的设备功能。

梯子位于船本地X=0。上下指令开始攀爬；`ShipLadderHatch` 根据两角色 `IsClimbing` 打开中心舱口。到达楼层后将脚底放到楼层上方，舱口恢复实体。替换船体时，保留左右甲板、独立中心舱口 Collider 和 `hatch.crew` 两角色引用，避免走路掉舱或梯子穿不过地板。

水下陷阱门与船上梯子舱口是两个组件。`WorldGenerator.trapdoorPrefab` 接独立 Trapdoor 资产，生成实例时 `TrapdoorGate.Configure` 按横/竖门洞配置实体尺寸。互动打开后关闭 barrier 碰撞，关闭后恢复；门不消耗货箱物品。替换门板时保留 barrier，正式美术可同时关闭 `fitPlaceholderSize` 和 `animatePlaceholder`，保留模型尺寸并自行制作开门动画。HUD交互优先级与生成位置见机制文档。

## 美术、Animator 与反馈替换

在 Prefab Mode 替换 `VisualRoot` 的几何子物体或整个视觉子树，保留稳定物理根及上述逻辑组件。重挂 `CrewActor.visualRoot/animator` 和 `CrewPresentation.visualRoot/animator`。导入模型的额外 Collider 应移除或明确放在稳定根，不要让装饰遮住交互点。

`CrewPresentation` 支持可选 Animator 参数：`Speed` 为 Float，`Swimming/Grounded/Downed` 为 Bool，`AttackTrigger` 为 Trigger。参数名是 public 字段，可改成现有 Controller 命名；缺失参数会跳过，不强制美术使用特定 Controller。船上 Speed 是扣除船速后的水平相对速度，站立搭船不会播放步行动画。建议关闭模型 Root Motion，让角色位置始终由物理控制。

`CrewActor.PresentationEvent` 发出 Jump、Land、Dive、Board、Melee、Fire、Hit、Downed、Revived、Winched。音效/粒子脚本可实现 `ICrewPresentationSink.OnCrewPresentationEvent(...)`，并放入 `CrewPresentation.eventSinks`。当前提供的是事件接口与占位几何，没有已经交付的正式音效、角色动画或特效素材。

资源和世界材质可分别换 `world.resourceMaterials` 与 `placeholderMaterials`。`LootPickup.tintPlaceholderVisuals` 控制裸资源按类型上色；使用正式美术时可关闭，货箱槽位仍能使用对应资源材质。敌人的材质与Prefab引用在 `GameSession`/`WorldGenerator` Inspector 暴露。

当前占位配色沿用HTML验证版的明亮海蓝、青绿、金黄及浅色按钮；船、人物和原料使用 `Assets/_LifeLine/Materials/` 中实际材质。新建资产使用新版配色，Preserve Existing不会自动改掉旧材质。需要把已有生成资产切到此配色时，显式运行 `LifeLine/Art/Apply Bright Prototype Palette`：它会更新库中指定名称的材质颜色及 `Prefabs/UI/ActionButton.prefab` 颜色，请先保存或另存自己的美术版本。这是占位材质更新入口，不代表已交付正式美术。

## 镜头与船上同屏设置

本地双人默认在船上共用全屏镜头；潜水员入水后自动切为左右分屏，返回船上恢复同屏。设置中的“船上镜头”可改成船上也分屏，选择保存在 `PlayerPrefs["LifeLine.View.SplitScreenOnShip"]`，重开场景仍生效。此开关只改变船上布局，水下仍为分屏。

`GameCameraRig.SetShipSplitPreference(bool)` 同时应用并保存选择，Inspector公开共享/分屏范围、跟随偏移和限界/遮挡参数。替换镜头时保留两套Camera、CinemachineBrain、虚拟相机和对应边界引用。`SetNetworkView` 只是将来按本机角色展示的接口，不建立在线会话。

## 输入与换绑

`Input/LifelineControls.inputactions` 包含 Captain 与 Diver 两个 map。每个 `CrewInputReader` 克隆共享资产，只启用对应 map；不会直接改共享输入资产。默认主要键位如下，设置界面和 HUD 会显示实际绑定。

| 操作 | 船长 | 潜水员 |
| --- | --- | --- |
| 移动 / 游泳 / 梯子 | WASD | 方向键 |
| 船上跳跃 | W | ↑ |
| 互动 / 持续扶起 | E | Enter |
| 收集（按住） | R（预留同类操作） | 1 |
| 近战 / 节奏键 | Space | K |
| 鱼枪 / 再按回收 | Q | 2 |
| 突进（按住） | LeftShift | RightShift |
| 信号 / 诱饵 / 藏身 | Z / X / C | . / / / M |
| 暂停 | Escape | Escape（界面去重） |

上下方向与 Jump 是独立绑定；改 Move 的上方向不会自动修改 Jump，可分别设置。键位界面跳过 composite 总头，逐个列出上/左/下/右子绑定。`BeginRebind(actionName,bindingIndex,callback)` 支持取消；设置后按角色保存到 `PlayerPrefs` 的 `Lifeline.Bindings.v1.Captain/Diver`。默认资产ID稳定，重启及重新加载场景后可恢复；Reset 仅删除所选角色的覆盖。

`ReadCommand()` 对 jump/interact/melee/fire 等按钮消费一次边沿；move/collect/sprint/interactHeld 保留按住状态。`interactHeld` 让权威 session 持续验证5秒扶起，不能用重复 interact 边沿冒充持续按住。暂停期间仍读取输入并交给界面，物理不移动。站点用 `controlsCaptured` 捕获该角色移动但继续读取小游戏指令，不应整体禁用 reader。

测试模式区别：Input System 在未播放的编辑器中默认处理 Editor 状态缓冲；player action 的初始状态检查和变化回调会跳过 Editor 更新，直接改成 Dynamic 也会被未播放状态的更新门控挡住。因此真实按键回调测试进入 PlayMode，设置公开的 ProcessEventsInDynamicUpdate 后使用公开 `InputSystem.Update()`，并在结束后还原更新/焦点设置。带类型参数的 Update 重载并非本项目可调用的公开接口。带独立3D PhysicsScene的测试也在 PlayMode 运行；测试禁用自动行为，再调用真实 tick 并明确模拟一次物理，避免一帧被模拟两次。暂停测试直接反射调用实际 Update，不使用在 EditMode 中会触发 ShouldRunBehaviour 断言的 SendMessage。

Input System 的键盘控件路径是 `<Keyboard>/1` 和 `/2`，不是 `digit1/digit2`。已有旧输入资产可显式执行 `LifeLine/Migration/Repair Legacy Digit Bindings`；先备份，再只改 Diver/Collect、Fire 的已知错误基础路径，保留绑定ID、其他自定义基础路径与PlayerPrefs换绑。不自动重建整份输入资产。

## 中英文与文案替换

`Runtime/Localization` 提供显示层本地化。默认可编辑资产位于 `Assets/_LifeLine/Data/Localization/DefaultLocalization.asset`。`LocalizationTable` 是可替换的 ScriptableObject，`entries` 每条包含稳定 `key`、中文 `zh`、英文 `en` 和 `fragment`。开发者在表资产 Inspector 修改文案，无需改 GameSession 的状态原文或配方逻辑；同一 key 应唯一。`LifeLine/Localization/Create or Extend Default Table` 只添加缺失key，保留已有人为文案；也可建立自己的表并改Manager引用。缺少目标文案时保留源文字，便于发现遗漏。

每个场景挂一个 `LocalizationManager`，引用同一表。`languageOverride` 为 `System/Chinese/English`；System 将系统中文、简体中文、繁体中文设为中文，其余设为英文。设置界面通过静态 `SetLanguage(GameLanguage)` 切换，选择保存到 `PlayerPrefs["LifeLine.Language.v1"]`；`LanguagePreference` 是用户选择，`GetCurrentLanguage()` 是解析后的实际语种。场景重载会读取选择，语言切换发送静态 `LanguageChanged` 与当前实例 `Changed`。

新UI优先用 `LocalizationManager.Current.Translate(key)` 或 `Format(key, args)`。格式表例如 `zh="{0}制作了{1}，数量{2}"`、`en="{0} crafted {2} × {1}"`；Format 支持数值格式参数并会翻译字符串物品名。旧动态文本由 `LocalizationTextBinder` 适配：挂在UI根以覆盖子 Text/TextMesh，或每场景单独一个 `scanWholeScene=true`，同时覆盖UGUI和世界标牌。它在 LateUpdate 捕获外部写入，保留源文本后翻译；切换语言从保留的源重新渲染，不能把翻译后的Text读回权威状态。

翻译顺序是完整 key/原文、完整 `{0}` 数字占位模板、最长源片段单轮替换。模板捕获的物品名也会翻译，数值保持原样。英文片段遵守词边界，`day` 不会破坏 `today`；富文本标签保持。为保证英语语序，包含数值、主语或道具的句子优先补完整模板；有歧义的短词设置 `fragment=false`，仅允许完整匹配。Binder默认跳过InputField用户输入，支持运行时新建标签；正式世界字体可关闭 `useRuntimeFontForWorldLabels` 并自行赋 TextMesh 字体/材质，默认占位标签会使用系统中文回退字库。

Manager 的 `FindUntranslatedChinese()` 或 Inspector 上下文菜单 `Find Untranslated Chinese` 会列出英语结果仍含中文的当前显示源，供打开各站点后补词条；也可传 `IEnumerable<string>` 检查一组预期状态。这是当前采集文本的诊断，不能代替完整流程的文案覆盖测试。运行时改表后调用 `table.NotifyChanged()` 或 `manager.RefreshTable()`；改Inspector资产会更新Revision并触发重绘。

## UI 替换与公开调参

MainMenu 与 Gameplay 都是场景内可编辑 UGUI 层级，EventSystem 使用 `InputSystemUIInputModule`。更换 HUD 布局时，重新连接 `GameHUDController` 的 Text/Image/Button、两侧 `CrewStationPanel`、`GameSettingsPanel` 与 `ControlsRebindPanel` 引用。换站点按钮皮肤时保留 Button、子 Text 与可布局的 RectTransform；小游戏仍调用统一入口，不要在 UI 复制一份库存、修理或制作逻辑。

`RuntimeUIFont` 可赋正式 Font 资产；为空时优先系统中文字库，最后回退 LegacyRuntime.ttf。字体和字号可以改，角色/物品名字显示不依赖替换几何。

主要 public 调参入口：

- `GameTuning`：行走/游泳/重力、氧气、背包、绳长、船速与电量、制作各档耗时、扶起、升级、天气、敌人、鱼获与炮塔。
- `RecipeDefinition`：成本、产出、工具解锁、电台阶段、恢复量、`craftTimeMultiplier`。`CraftingManager`实际处理制作提交、进度和完成，并写回session共享状态。
- `CrewActor`：Collider/地面mask、地面探测、梯子宽度/速度、楼层/水面/世界边界、碰撞皮肤；`ShipMotor`：航线西/东边界。
- `WorldGenerator`：种子、房间/门洞尺寸、生成层、深度、各层资源权重、洞穴概率及资源/敌人Prefab。
- `GameCameraRig`：共享/分屏镜头范围、跟随偏移、限界矩形与遮挡mask；`NightVisibilityView`：夜间显示引用与参数。
- `GameSession` 和敌人组件：实际Inspector暴露的升级成本、战斗、生成与救援参数；以数值导出表为核对来源。

编辑调参资产后正常保存即可。Play Mode 中临时改场景组件值不会自动成为永久配置；确认效果后退出播放，将值写回原资产/Prefab再保存。
